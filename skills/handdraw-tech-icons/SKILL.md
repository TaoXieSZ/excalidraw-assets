# 手绘技术图标

目标：将组件的关键技术语义压缩成易辨认的小图标。普通文本模型准备小规格；图像工具负责绘制。默认风格是方形边框、浅色铅笔排线、白色主体和自然黑色复描。用户指定的风格、标签或其他约束优先于这些默认值。

## 执行

1. 读取组件定义和最新用户纠正。区分功能事实与视觉比喻：文档里的“河流、信件、工匠”不自动意味着要画风景或人物。使用 [规格提取规则](references/brief-prompt.md) 和 [JSON 示例](references/brief.example.json)，写入任务目录的 `data/brief.json`。通常最多三个关键语义、四个主体图形、一个辅助元素；复杂组件先选最有区分度的部分。
2. 保留输入输出方向、审批/隔离条件、同步/异步语义；不知道的关系不要补画。真正影响图义的歧义才询问用户，其余先做小样。
3. 从本 skill 所在目录定位并运行脚本，不依赖当前工作目录或原作者的绝对路径：

   ```bash
   python3 "<skill-directory>/scripts/compile_prompt.py" "<task-directory>/data/brief.json" --out "<task-directory>/data/image-prompt.txt"
   ```

   脚本仅编译提示词，不生成图像。若用户覆盖默认画风，在编译输出中替换对应风格段，保留最终实际使用的提示词；不要让模板覆盖用户意图。
4. 用当前环境可用的图像生成工具实际生成一个小样。附上 [内置参考图](assets/style-reference.png)，明确它只供画风参考。Codex 有内置 `image_gen` 时优先使用；其他 Agent 使用其已配置、支持参考图的绘图工具。不要假设工具名、模型名、密钥或网络能力在每个 Agent 中都相同。没有图片工具时交付提示词与参考图，明确“尚未生成图片”，不冒充成功。
5. 检查生成图：关键语义是否保留、方向是否正确、缩小后是否可辨认、图形是否简洁、是否误复制参考中的服务器/水桶。失败时只修改具体问题并保留已认可部分。通常两轮仍不收敛就回到简化规格；报告局限而不是继续堆否定词。
6. 保存并展示实际产物。文件按 `<task>/assets/`（图片）、`data/`（规格和最终提示词）、`output/`（分享文件）组织。生成图若位于工具默认目录，复制到任务目录。报告实际使用的参考图、图像工具与产物类型。

“画出来”必须有真实工具执行和图片展示；只输出方案或提示词不算完成。用户只要提示词时不调用图片工具。

## 输出模式

- **PNG 小样**：默认先验证符号和风格；如实说明仍是位图。
- **可编辑 Excalidraw**：用户要求时继续执行 [原生重绘与导入](references/excalidraw.md)，不把 PNG 改扩展名冒充素材库。已有原生图标的小改动优先修改原生元素。
- **多图标**：锁定同一张已认可参考图，逐个替换组件规格。不要为每个图标重新探索画风。

不能保证任意廉价模型、任意图像工具获得相同效果。参考图与模板降低的是文本规划的自由度；实际画面仍取决于绘图工具。不要宣称未经实测的弱模型等效或成本收益。

生成、安装与公开发布是不同操作。仅为公司组件画图不构成公开上传授权；没有用户发布要求时保存在任务目录。
